# csrf-sec v0.9.2 - Third Review

**A third adversarial review, fixed token vectors, and the release paperwork 1.0 needs.** A reviewer with no part in 0.9.1 was asked to break it, starting with the optional expiry it added. Like the two reviews before, they found no way to make `verify` or `check` pass a request built without the key or the victim's token. They did find a way to pass a one-time token twice after a configuration change, and smaller problems; each is fixed here with a test that failed first (`tests/review.rs`, `r3_*`).

## Security

- **`no_expiry` moved the default one-time lifetime.** With a lifetime under an hour, turning on `no_expiry` raised the default one-time lifetime from the lifetime to an hour. Two nodes sharing a store, or an old and a new `Csrf` around one store, then disagreed without anyone setting it, and a used one-time token passed again once the shorter-lived record was purged. The default is now the same with or without expiry; set `once_lifetime` explicitly in a cluster and compare `once_lifetime()` across nodes.
- **One-time `GET` links were not checked.** A one-time binding is now checked and consumed on safe methods too, in every mode, as the documentation said. Before, `check` passed a `GET` with a one-time binding without looking at the token.
- **Rotation and long one-time tokens.** When the one-time lifetime is longer than the lifetime (possible with `no_expiry`), rotation now keeps the old key until the last one-time token it signed has expired.
- **A broken clock with `no_expiry`.** A clock past 2156 (a time in milliseconds, say) is refused as `expired`, as it is with expiry on.

## Added

- **Token test vectors.** Eight tokens across both layouts and a key fingerprint, from fixed inputs (`docs/TEST_VECTORS.md`, `tests/vectors.rs`). A second implementation of the format, in Python with a BLAKE3 written from its specification, rebuilds every vector in CI (`dev/reference/vectors.py`). All nine matched on the first run, which also shows the format description in `docs/API.md` is complete.
- **`cargo semver-checks` in CI**, against the last release on crates.io.
- **`SECURITY.md`**: report vulnerabilities privately to me@jamesgober.com; acknowledgement within 72 hours.

## Documentation

Under `no_expiry`, the session value must be regenerated at login, never reissued after logout, and never a user or account id. Rotation with `no_expiry` ends forms older than the grace. The minimal `NonceStore` example is marked test-only, since it never forgets.
