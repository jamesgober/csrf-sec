# csrf-sec v0.4.0 - One-Time Tokens

**Single use for high-value actions, without giving attackers a lever on the store.** v0.4.0 adds one-time tokens: bind a form to a `NonceStore`, and its token passes exactly once.

```rust
let store = MemoryStore::new(100_000);
let pay = Binding::new(session_id).scope("POST /pay").once(&store);

let token = csrf.issue_with(&pay)?;        // 102 characters; the store is not touched
csrf.verify_with(&pay, submitted)?;        // passes once; again: AlreadyUsed
```

## Highlights

- **The store remembers only what was used.** A one-time token is a signed token with a 128-bit random nonce inside the MAC. The MAC already proves the token was issued by this key ring, so the store does not track issued tokens at all: issuing is stateless, and the store records a nonce only when it is used, with one atomic set-if-absent call. Pages are rendered far more often than forms are submitted, so this removes the bulk of the store's writes and memory.
- **The MAC comes before the store.** The MAC, the validity window, and the scope are checked first; only a token that passes all three reaches the store. A cross-site attacker submitting a wrong token with the victim's cookies cannot burn the victim's token, and forged requests never load a shared store. A spy-store test proves it: forged, wrong-session, wrong-scope, expired, future, foreign-key, and malformed tokens make zero store calls, and so does issuing.
- **Exactly one winner.** Eight threads verifying the same token at once: exactly one passes, every round.
- **Fail closed.** A store that cannot answer refuses the request (`StoreUnavailable`). In every mode, including `PolicyOnly`, a one-time binding checks the token.
- **`MemoryStore`, restart-safe.** 64 shards behind their own locks, bounded and expiring. A full shard drops expired records and otherwise refuses rather than forgetting a used token. Because its memory dies with the process, it refuses every token issued at or before the second it started, so a restart can never let a used token pass again. For a cluster, implement `NonceStore` over a store every node reaches.
- **Still allocation-free.** Issue, verify, and reuse of a one-time token with an allocation-free store make zero allocations, measured.
- **Format checked against its description.** A test rebuilds a version-2 token from the documented format with crypt-io directly and compares it byte for byte.

## Changed

- The store design written at the `0.2.0` design lock (record on issue, remove on verify) is replaced by a single `consume` on verify, for the reasons above.
