# csrf-sec v0.8.0 - Alpha

**Reviewed against a real adapter and real browsers, and every mutant caught.** v0.8.0 keeps the public API exactly as it was: building a complete adapter found nothing missing. What changed is the evidence behind it.

## A complete adapter, checked in a real browser

`examples/server.rs` is a full adapter with no dependencies: a small HTTP server that renders a form with a token, checks posts with `csrf.check`, and serves an "attacker" page from a second origin. Run it with `cargo run --example server`. In a Chromium-based browser:

| From | The browser sent | Verdict |
|---|---|---|
| the site itself (`localhost:7878`) | `Sec-Fetch-Site: same-origin` | allowed, on Fetch Metadata |
| another site (`127.0.0.1:7879`) | `Sec-Fetch-Site: cross-site` | refused, `cross_site`, before any token work |
| a sibling origin (`localhost:7879`) | `Sec-Fetch-Site: same-site` | refused, `cross_site` (sibling subdomains are off by default) |

The adapter needed nothing the API lacks, so the API is unchanged. `docs/API.md` now has a "Writing an adapter" section: where each value comes from, a checklist, and two rules the demo made concrete. Pages that carry a token must never be stored in a shared cache (`Cache-Control: private, no-store`), because a cached page served to someone else hands them the first user's token; and a token must never travel in a URL.

## Mutation testing

cargo-mutants changes the code one small edit at a time (flip a comparison, swap an operator, return early) and checks that some test fails for every change. The first run left 29 of 764 mutants alive. Two were real gaps: in the decoder's tail, swapping `|` for `^` in the error accumulator lets two invalid characters cancel each other's error flag, and no test put two bad characters in one group. The code was right, but a later edit could have broken it unseen; now an exhaustive test covers every pair of positions, and the decoder accumulates one flag per character. Several more were weak tests, each now pinned (the default lifetime's value, an even number of equal key deviations, the `Referer` fast path against a garbage own origin, the 4 KiB header limit, the pad pool's threshold).

The final run: 726 mutants, 655 caught, 71 that do not compile, none missed. The remaining equivalent mutants (an OR of bit fields that never overlap equals an XOR, for example) are listed with the reason for each in `.cargo/mutants.toml`. CI now runs mutants on the changed code of every pull request, and a weekly workflow runs the full set.
