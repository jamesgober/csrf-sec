# csrf-sec v0.6.0 - Measured

**Every cost is now a measurement, and the hot paths are tuned.** v0.6.0 adds a benchmark suite, a comparison with the `csrf` crate, and four measured improvements. No public API changed.

## Numbers

Linux, AMD Ryzen 9 9950X3D, Rust 1.99, release profile; `docs/PERFORMANCE.md` has the method and the full tables.

| Call | Time |
|---|---|
| `verify_at` | 110 ns |
| `issue_at` | 112 ns |
| `check_at`, `Strict`, `Origin` + token | 150 ns |
| layer 1 on `Sec-Fetch-Site` | 1.3 ns |
| a cross-site request refused | 23 ns |
| a wrong-length token refused | 3.4 ns |
| a forged token refused | 116 ns, the same as a valid one |

Zero allocation on every hot path and rejection path, asserted on Linux, macOS, and Windows.

## Against the `csrf` crate

| Per request | csrf-sec | `csrf` 0.5 HMAC | `csrf` 0.5 AES-GCM | `csrf` 0.5 ChaCha20 |
|---|---|---|---|---|
| issue | **165 ns** | 530 ns | 1.11 µs | 3.34 µs |
| verify | **141 ns** | 430 ns | 407 ns | 2.46 µs |

3.2 times faster to issue and 3.1 times faster to verify than the fastest variant of the standalone Rust CSRF primitive, while also being session-bound, masked per response, allocation-free, and constant time end to end. The harness lives in `dev/bench-compare`, outside the published crate, so its third-party crates never reach csrf-sec users.

## Tuned

- **Tag comparison.** One 128-bit XOR tested once, instead of a per-byte comparison with barriers: from 50 ns to about 1 ns, with no loop to exit early and no branch on the data.
- **base64url.** Full blocks are processed eight characters per 64-bit word, still with no lookup table and no branch on token bytes: decode 29 ns, encode 20 ns. Every lane is tested against the one-character code for every byte value.
- **Origin parsing.** The scheme is split at its first colon, character classes are 128-bit sets, and a value byte-identical to the site's own origin needs one parse: a `Referer` match went from 51 to 23 ns.
- **Cross-site requests.** When the browser says another site sent the request, only the allowlist can pass it, so a cross-site refusal takes 19 ns, and no parsing at all without an allowlist. Attacks are now the cheapest requests to refuse.

## Changed

- With `Sec-Fetch-Site: same-site` or `cross-site`, the site's own origin no longer counts as allowed; only `Builder::allow_origin` entries do. A request the browser calls cross-site cannot be vouched for by our own origin.

## What's next

`0.7.0` is the hardening phase: an attack test for every threat T1 to T15, property tests, fuzz targets for the decoder, the verifier, and the policy, and a statistical timing test of the tag comparison and the codec.
