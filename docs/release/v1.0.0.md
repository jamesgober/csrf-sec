# csrf-sec v1.0.0 - Stable

**The first stable release.** csrf-sec decides whether a state-changing request came from your own page, for this session: a request origin policy on the headers browsers send (`Sec-Fetch-Site`, `Origin`, `Referer`), and a signed, session-bound token masked fresh on every response. With 1.0 the public API is frozen until 2.0, and the token format is frozen for the 1.x line: a token issued by any 1.x release verifies on any other.

There are no API changes since 0.9.0. 1.0.0 is the commitment to a surface built, measured, attacked, and reviewed across the 0.x series.

## What it gives you

- **Three calls.** `Csrf::new(key)`, `issue(session)`, `check(&facts, session, token)`. A refusal names its reason (`bad_mac`, `cross_site`, `expired`, ...) with a severity hint for detection; the client gets a plain 403.
- **Two layers.** The request policy refuses cross-site unsafe requests in about a nanosecond on Fetch Metadata, before any token work. The token is keyed BLAKE3 over the session id (and optionally one action), a 128-bit tag compared in constant time; the session id never appears in it.
- **Fast and allocation-free.** Issue 112 ns, verify 110 ns, a strict check 150 ns (Linux, Ryzen 9 9950X3D); 2.9 to 20 times faster than the `csrf` crate. No allocation, no lock, and no shared counter on any request path, asserted by a counting-allocator test on Linux, macOS, and Windows.
- **Rotation without logouts.** A key ring with signing, accepted, and retired keys, public fingerprints to compare across a cluster, and two-step rotation so no node ever sees a token from a key it does not hold.
- **One-time tokens** for payments and deletions, through a store you choose; the MAC is checked first, so forgeries never reach the store.
- **Runs anywhere.** Linux, macOS, Windows, and bare metal (`no_std` with `alloc`), stable and MSRV 1.85, `#![forbid(unsafe_code)]`, no third-party runtime dependency of its own.

## How it was checked

- Two independent adversarial reviews, the second aimed at the first one's fixes. Neither found a way to make a request built without the key or the victim's token pass. Every other finding is fixed, each with a test that failed first (`tests/review.rs`).
- Every threat in the design (T1 to T15) has an attack test that must fail to get through; every invariant has a property test; four fuzz targets; every mutant of the crate is caught by a test.
- Constant-time checks run at length: 2,000,000 samples per class on the decoder and the tag comparison.
- A complete HTTP adapter checked against real browsers.
- For 1.0, every claim in the README, `docs/API.md`, and the rustdoc was compared with the build and corrected where it differed; the README Quick Start and every example in `docs/API.md` compile and run as doctests.

## Stability

- **Additions only until 2.0.** `#[non_exhaustive]` enums (`Reason`, `Error`, `StoreError`, `OriginCheck`, `KeyRole`, `Mode`, `MethodClass`, `FetchSite`) may gain variants; match them with a wildcard arm.
- **Token format frozen for 1.x**, including the MAC input and the subkey labels. A new layout would get a new version byte, and older ones would keep verifying.
- **Reason names are stable** for logs and dashboards.
- **MSRV 1.85**; raising it is a minor release.

## Since 0.9.0

- Property tests for every invariant that lacked one, and a no-allocation test that reaches every refusal reason.
- Documentation corrected where the audit found it disagreed with the build (`CHANGELOG.md` lists each).
- `Error::InvalidLifetime` now names the one-time lifetime case.
- Upgrading from 0.8: see the 0.9.0 entry in `CHANGELOG.md` (one-time lifetime across a cluster, origin parsing, store sizing).
