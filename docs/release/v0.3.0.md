# csrf-sec v0.3.0 - The Core

**Tokens, the request policy, and all three API tiers.** v0.3.0 is the first release with working code: csrf-sec issues and verifies signed, session-bound tokens masked per response, applies the request origin policy over Fetch Metadata, `Origin`, and `Referer`, and combines them by mode. Key rotation logs nobody out, on one node or across a cluster.

## Three calls

```rust
let csrf = Csrf::new(key)?;
let token = csrf.issue(session_id)?;                 // 59 characters, different on every call
csrf.check(&facts, session_id, submitted)?;          // request policy + token
```

`Binding` adds a scope (one action) and the previous session id; the builder configures keys, lifetime, skew, mode, and allowed origins; the `_at` calls take the time and the randomness source explicitly and work without `std`.

## Highlights

- **Accurate reasons, decided after the MAC.** A forged token is `bad_mac` (severity 40), an old tab is `expired` (1), a tab opened before login is `stale_session` (1), and an unscoped token on a scoped form is `wrong_scope` (20). A forgery can never lower its own severity.
- **Zero allocation, measured.** A counting-allocator test runs issue, verify, check, and every rejection path and asserts that nothing allocates. Nothing on those paths takes a lock.
- **Tamper tests that leave nothing out.** Every character of a token replaced with every other byte value, and every bit of the decoded token flipped, is refused. A token never verifies under another session id, scope, or key, and `("ab", "c")` and `("a", "bc")` are different bindings.
- **The format is checked against its description.** A test rebuilds a token from the documented format using crypt-io directly and compares it byte for byte with what the crate issues.
- **Constant-time, canonical codec.** base64url is encoded and decoded with arithmetic masks instead of lookup tables, and only canonical text decodes.
- **Two-step rotation for clusters.** Keys can be accepted (verify only) on every node before any node signs with them; `rotated` promotes a staged key and keeps the old one verifying for one lifetime plus skew.
- **Strict origin parsing.** Scheme and host compared without case, default ports normalized, `null`, paths, user information, and malformed values never match.

## Changed

The request policy, modes, and builder moved into this release from `0.4.0`, so `check` ships complete. One-time tokens move to `0.4.0` (PLAN D-027).

## Dependencies

`crypt-io` 1.1 (keyed BLAKE3, constant-time tag comparison, `Zeroizing`) and `mod-rand` 1 (OS CSPRNG, with `std`). Both are first-party; crypt-io's RustCrypto primitives are the accepted audited-crypto exception.

## What's next

`0.4.0` adds one-time tokens: a signed token with a nonce, checked against the MAC before a `NonceStore` is touched, with a sharded in-memory store.
