# csrf-sec v0.9.3 - Polish

**Cluster tests and documentation that matches the code.** Nothing the crate does has changed. This release adds the tests a cluster depends on, corrects nine places where the documentation had fallen behind 0.9.2, and checks the rest of the 1.0 list that can be checked before a real integration.

## Added

- **Cluster tests** (`tests/cluster.rs`). Several nodes, each its own `Csrf` built from the same configuration, share one one-time store that offers only set-if-absent with an expiry: the contract of a networked key-value store such as Redis `SET NX PX`. Every one-time token passes exactly once with six nodes racing on 300 tokens; a two-step key rotation under traffic keeps every outstanding token valid on every node, and a node that skips the first step is refused as `unknown_key`; nodes whose clocks are apart by up to the skew never pass a used token again, through its whole life and after the store drops the record; a store outage fails closed on every node and consumes nothing; a key deployed with the wrong bytes shows in its fingerprint and its tokens never reach the store. Each test was shown to fail against a store that forgets, one that forgets too soon, and one that answers yes during an outage.

## Fixed

Documentation only:

- Safe methods and `Mode::PolicyOnly` were described as never checking a token. A one-time binding always checks and consumes its token, whatever the method and mode (since 0.9.2).
- `SECURITY.md` listed every CI job as running on three platforms and two toolchains; it now says which run where, and that mutation testing covers pull requests and a weekly full run.
- `Verified::retired_key`, `Error::InvalidLifetime`, `Error::InvalidRetireTime`, `Builder::retired`, and `Builder::no_expiry` now give the 0.9.2 rotation grace, the one-time lifetime cap under `no_expiry`, and the exact time bounds. `Error::InvalidLifetime`'s message mentions `no_expiry`.
- Smaller corrections: two subkeys per key id, which test vectors take the streamed MAC path, and that a one-time token adds a store call to "no allocation, no lock".

## Checked

- The weekly full mutation run covers this source: 788 mutants, every viable one caught.
- The hot paths since v0.9.0 add a few instructions per call; `PERFORMANCE.md` stands until the full gate re-measures it on a quiet machine.
