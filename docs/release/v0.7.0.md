# csrf-sec v0.7.0 - Hardened

**Every threat attacked, every invariant fuzzed, every secret-dependent path timed.** v0.7.0 changes no library code. It adds the tests that try to break csrf-sec, and they run on every push.

## Attack tests

`tests/attacks.rs` plays the attacker once for each threat in the plan, and every attack must fail:

| Threat | The attack |
|---|---|
| T1 classic CSRF | an auto-submitted form from another site, with modern headers, old headers, and no headers |
| T2 login CSRF | the attacker's login token submitted from the victim's browser |
| T3 forced logout | a cross-site logout post, and a logout link |
| T4 BREACH | 2,000 responses for one session: no position repeats, no 8-character run repeats |
| T5 session replay | a stolen token in another session, including one-character variations of the session id |
| T6 action replay | a comment token on a transfer form |
| T7 cookie tossing | the attacker's own valid token carried into the victim's request |
| T8 forgery | 50,000 random well-formed tokens, and tokens signed under the attacker's key with any key id |
| T9 timing | tags right in 15 of 16 bytes, refused exactly like wrong ones |
| T10 key compromise | tokens minted with a stolen key, before and after rotation and retirement |
| T11 denial of service | a thousand 16 MiB tokens and a 1 MiB origin |
| T12 clock skew | tokens from a clock one second past the skew, and ten years ahead |
| T13 safe-method look-alikes | `get`, `GET `, `GET\0`, `HEAD\t`, `TRACE` |
| T14 `Origin: null` | null origins, stripped referers, and a referer with user information |
| T15 cross-site navigation | a top-level cross-site post, in every mode that runs the policy |

## Fuzzing with invariants

Four cargo-fuzz targets assert the security property they exercise, not only that nothing panics: nothing the fuzzer makes ever verifies; a mutated real token verifies only if its raw token is unchanged (remasking is public, so that is not a forgery); the policy passes a cross-site request only through the allowlist and never passes `Origin: null`; a one-time token passes at most once, checked against a model. Locally, 60 seconds per target ran about 17.5 million inputs with no finding; CI runs each for 30 seconds on every push.

## Constant time, measured

`tests/timing.rs` uses the dudect method: two classes of input that differ only in secret-dependent ways, interleaved at random, compared with Welch's t-test. Across 2,000,000 samples per class, the tag comparison reads t = 1.8 and decoding t = -2.6, under the 4.5 line where a leak would begin; a control (a real difference) reads t = 175,000, so the method works. On the CI runner, with 200,000 samples, they read -0.35 and -2.41.

One finding along the way: the first runs read t = 60.7 locally and -16.4 on the CI runner for the tag comparison. The generated code has no data-dependent branch (the comparison compiles to `mov`, `or`, `sete`; the decoder to straight-line vector code), and the cause was the test: its two inputs lived at different addresses, so cache-line straddles and 4 KiB aliasing told them apart, not their data. The test now copies every sample into one shared buffer before timing it.

## Property tests

`tests/properties.rs` (proptest) covers the unbounded spaces: any session, scope, time, and key round-trips; any character change fails; another session, scope, or key fails; arbitrary bytes never verify; the policy is total and fails closed; the validity window is exact to the second.
