# csrf-sec v0.9.0 - Release Candidate

**Two independent adversarial reviews, and every finding fixed test-first.** For v0.9.0 a reviewer with no part in the code was asked to break it: read the design, the API, and every source file, and find any way to get a request through that should not pass. They found none: no way to make `verify` or `check` accept a request built without the key or the victim's token, and they confirmed the MAC input, the decoder, the check order, the tag comparison (in the compiled assembly for four targets), the time arithmetic, the key ring, the origin parser, and the redaction of secrets. They did find one medium and several low issues. A second reviewer then attacked those fixes, again found no forgery, and found two ways a used one-time token could pass a second time. Every finding of both reviews is fixed here, each with a test that failed first (`tests/review.rs`).

## Upgrading from 0.8

- **Nodes that share a one-time store must use the same one-time lifetime.** 0.8's one-time tokens lived the whole lifetime; 0.9's default is one hour. During a rolling upgrade set `.once_lifetime(lifetime)` on the 0.9 nodes, and lower it everywhere at once after the last 0.8 node is gone. A mixed setting would let a token used on a short-lived node pass once more on a long-lived one.
- An `own_origin` that does not parse (a trailing slash, a Unicode host) now refuses requests that carry `Origin` or `Referer` but no Fetch Metadata, where 0.8 left them to the token. Pass the serialized origin (`https://xn--bcher-kva.example`).
- With nothing configured, a `Referer` that is not a URL (from a non-browser client) is refused.
- Size `MemoryStore` at 512 times the session limit (32,768 for the default); a smaller store lowers the limit to fit.

## Security

- **One session could fill the one-time store (medium).** An attacker's own session, a guest session is enough, could submit its own valid one-time tokens until `MemoryStore` was full, after which every other user's one-time actions were refused for up to twelve hours; each refusal also scanned the full shard under its lock. Now each session may hold at most 64 records at once (`with_session_limit`), a session's records live in one shard, a full shard with nothing expired refuses in constant time, and one-time tokens have their own lifetime of one hour by default (`Builder::once_lifetime`), so records last an hour and a minute, not twelve hours.
- **A malformed own origin turned the origin check off.** A trailing slash in configuration (`https://example.com/`) made the `Origin` and `Referer` checks pass everything to the token. A malformed own origin now matches nothing.
- **A malformed `Referer` slipped through when nothing was configured.** It is now refused, as the documentation already said and as `Origin` already was.
- **A clock stepping back across a restart.** `MemoryStore::new` now starts one minute ahead of the clock, so a step back of up to a minute cannot let a used token pass again; a clock before 2020 makes the store refuse everything instead of turning its restart protection off.
- **Milliseconds where seconds were meant.** A retire time in milliseconds kept a retired key valid for centuries, and `purge_expired` in milliseconds forgot every used nonce. Times past the range a token can reach now fail closed (`Error::InvalidRetireTime`, `Error::Clock`, or no purge).
- **A purge followed by an earlier clock (second review).** Once a record was purged, a verify on a clock that read earlier than the purger's (a clock stepped back, or zero skew and a one-second race) found the nonce unused. `MemoryStore` now remembers the latest expiry it dropped and refuses anything that expires before it, which never refuses a valid token on a clock that moves forward.
- **An undersized store (second review).** At the old sizing guidance one session's quota equalled its whole shard. A session may now hold at most an eighth of a shard whatever its limit, and the guidance is 512 times the limit.
- **Key copies in freed memory (second review).** The builder's key buffer is reserved up front and never reallocates, the subkey vector is sized before it is filled, and the expected tag is wiped after each comparison.

## Changed

- Rotation keeps the old key one second longer, through the last valid second of a token a peer up to the skew ahead could have signed.
- `MemoryStore`: size it at 512 times the session limit or more (32,768 for the default), since a session's records share a shard and a session may hold at most an eighth of one.
- The subkey comparison used for promotion no longer copies key material into an unwiped value, and the unsent half of each MAC output is wiped.

## Documentation corrected

The review also caught text that sounded right and was not:

- The MAC does not stop a planted session cookie. If an attacker can plant the session cookie, they can plant a session they hold a token for; the `__Host-` prefix and, in `Strict` mode, the request policy are what stop that. The cookie guidance and the "no server-side session" recipe now say so, and `tests/review.rs` shows the attack passing in `TokenOnly` and refused in `Strict`.
- Adapters must pass the effective method after any override, and never let an override turn a safe method unsafe.
- `policy()` returning `Ok(NoFacts)` is not a pass; gate with `check`.
- A forger can choose to be reported as `malformed` or `unknown_key`, so detection layers should score every non-benign reason, not only `bad_mac`.
- The literal keys in examples are public placeholders.
- `rotated` refuses on a broken clock; for an emergency rotation there, build a new `Csrf` with the builder.
- Many sessions can still fill a one-time store; rate-limit one-time issuing per client and alert on `too_many_uses`.

## Added

`Builder::once_lifetime`, `Csrf::once_lifetime`, `DEFAULT_ONCE_LIFETIME`, `MemoryStore::with_session_limit`, `MemoryStore::session_limit`, `StoreError::SessionLimit`, `Reason::TooManyUses` (a session over its one-time quota, told apart from a store outage), `Error::InvalidRetireTime`, and `NonceUse::new` for testing custom stores.
